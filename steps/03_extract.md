Implement step 3 of SPEC.md: automatic rejection extraction from conversation text. Read `rmg/models.py` for Record/Fingerprint/enums.

Create `rmg/extract.py` and `tests/test_extract.py`. Stdlib only (re).

API:
- `REJECTION_PATTERNS`: list of regexes (case-insensitive) covering: "we already tried that", "already tried", "didn't work"/"did not work", "don't suggest that again", "scrap that", "ruled (that|it) out", "not profitable", "too expensive", "latency kills it", "decided against", "failed in testing", "move on", "that approach is dead", "only reconsider if ...", "no more X", "forget (about) X".
- `UNCERTAINTY_PATTERNS`: "not sure", "maybe", "let's think", "another way?", "perhaps", "might", "I wonder". A message whose only signal is uncertainty yields NO records. If a message contains a rejection pattern AND an uncertainty word, still no record only when the rejection phrase itself is hedged (e.g. "maybe scrap that?"): treat a rejection phrase preceded within 3 words by maybe/perhaps/not sure as hedged.
- `extract_rejections(messages, now=None) -> list[Record]` where messages is a list of `{"role": "user"|"assistant", "content": str}` (also accept a plain string = one user message). Only user messages create rejections. The rejected idea is the most recent assistant proposal before the user message (first sentence of that assistant message stripped of "I suggest"/"We could"/"Let's"/"How about"), or, if the user message itself names it (e.g. "Scrap the polling idea", "we already tried copy trading"), the named noun phrase. Fill: canonical_idea, original_discussion (assistant + user text), rejection_reason (the user sentence), fingerprint.mechanism (the idea), fingerprint.why_failed (reason), rejection_type (CONDITIONAL with reconsider_if = text after "only reconsider if" / "unless"; FAILED_EXPERIMENT for "tried"/"failed in testing"/"didn't work"; PREFERENCE for "I don't like"; else HARD), fingerprint.conditions_to_reconsider = reconsider_if.
- `is_uncertain(text) -> bool`, `find_rejection_phrase(text) -> str|None`.

Tests: each listed phrase yields exactly one record with a non-empty canonical_idea when preceded by an assistant proposal like "I suggest we poll the API every second."; "only reconsider if latency is under 50ms" -> CONDITIONAL with reconsider_if containing "latency"; mild uncertainty messages ("not sure about that", "maybe", "let's think about it", "another way?") produce zero records; assistant messages alone produce zero records.
