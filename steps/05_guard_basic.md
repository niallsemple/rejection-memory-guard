- `extract_proposals(message) -> list[str]`: split a candidate agent message into sentences/clauses (split on . ! ? ; newlines and bullet markers) and keep ones that look like proposals (contain verbs like use, try, poll, build, add, switch, copy, mirror, follow, implement, could, should, suggest, propose, let's, how about) or, if none match, all non-empty sentences.
- `@dataclass GuardResult`: candidate, decision (Decision), matched_rejection (dict|None: id, canonical_idea, rejection_reason), similarity (float), reason (str), conditions_changed (bool). `to_dict()` and `to_json()` producing exactly the keys `candidate, decision, matched_rejection, similarity, reason, conditions_changed` (decision as string).
- `class Guard`: `__init__(ledger, embedder=None, llm_judge=None)`. `check(message, context=None) -> list[GuardResult]` (one per proposal) and `check_one(proposal, context=None) -> GuardResult`.
  Matching for each ACTIVE/REOPENED rejection: `sim = similarity(proposal, record.match_text())`; also rule signals: `shared_concepts = concepts(proposal) & concepts(record.match_text())`, alias hit (any alias substring in proposal, case-insensitive), mechanism overlap (similarity to fingerprint.mechanism). NEVER decide on similarity alone: BLOCK requires (sim >= 0.45 AND (shared_concepts or alias hit or mechanism sim >= 0.4)). WARN when sim >= 0.3 or shared concepts exist but BLOCK conditions are not met. Otherwise ALLOW. Choose the best-matching record.
  On BLOCK: `ledger.increment_reproposal(id)`, `ledger.log_event("block", id)`; reason = "Previously rejected: <canonical_idea>. Reason: <rejection_reason>". On WARN: `log_event("warn", id)`, reason explains the difference ("Similar to rejected '<idea>' but differs: ..." listing concepts present in only one side). ALLOW: reason "No matching rejection".
  Optional `llm_judge(proposal, record) -> str|None` callable may return "BLOCK"/"WARN"/"ALLOW" to downgrade or confirm a BLOCK; ignore if None.
